# Roadmap scenario template combinations

Start with the [shared base](../roadmap-template.md); insert only selected modules.
These recipes are project recommendations, not four mandatory document formats.
Keep one editable authority per fact and remove author guidance from filled outputs.

| Scenario | Primary perspective | Starting combination | Filled example |
| --- | --- | --- | --- |
| [Iteration product](iteration-product.md) | Iteration goals | Requirements + iterations; versions/release events when batch delivery applies | [Complete example](../../references/scenarios/iteration-product/roadmap.md) |
| [Continuous flow](continuous-flow.md) | Workflow and flow evidence | Requirements + flow; optional actual release/acceptance points | [Complete example](../../references/scenarios/continuous-flow/roadmap.md) |
| [Staged delivery](staged-delivery.md) | Phase deliverables and exit conditions | Requirements + phases + significant acceptance events | [Complete example](../../references/scenarios/staged-delivery/roadmap.md) |
| [Discovery pilot](discovery-pilot.md) | Learning goals and exit decisions | Requirements + discovery/pilot phases + evidence-review points | [Complete example](../../references/scenarios/discovery-pilot/roadmap.md) |

Add [timeline](../modules/timeline.md) only when useful timing facts exist. Single
is a starting layout, not a forced choice; preserve existing split layouts. Hybrid
teams can combine modules with a source-backed rationale. See the
[selection guide](../../references/scenario-selection.md) for intake and practice evidence.
