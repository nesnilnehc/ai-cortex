# Iteration product recipe

Use when: The team works in fixed cycles and builds product increments.

## Compose

Use the [shared base](../roadmap-template.md) with [iterations](../modules/iterations.md), [versions](../modules/versions.md), [milestones](../modules/milestones.md).
Requirements, direction, priorities, sources and revision history remain common.
Add the [timeline module](../modules/timeline.md) when dates/windows are known.

## Recommendation and tailoring

Use iteration goals as the near-term anchor. Add versions when work ships in named batches, and significant acceptance/release events for coordination.

Omit phases unless work genuinely changes purpose/risk/exit conditions. If delivery is continuous, omit version batches that do not exist.

## Intake and review

First read existing norms, roadmap, boards and release/acceptance records. Ask only
missing work mode, delivery mode, audience and constraint facts. Explain the proposed
primary/supporting/omitted views and maintenance cost. Reuse an existing choice;
changed context gets a focused reconsideration, never an automatic reset.

Review near-term goals each iteration and delivery scope when evidence changes; do not wait for iteration review to release a usable increment.

Start single for a new small plan; use linked detail when readers, owners or update
cadence justify it. Preserve an existing layout/destination. No default plan-size
quota or additional approval gate is implied by this recipe.
