# Production and verification

## Source, slide order, and rendering

- Find the source in the user-specified local path, sync folder, or connected document. Record the local path or online revision and map each slide number to its rendered image and script. Hash local source files with SHA-256 to distinguish versions with the same name. If a synced file cannot be opened, check whether the full file is available locally or can be retrieved through the authorized connection.
- For PPTX, read slide order from `ppt/presentation.xml`. Follow package relationships to the slides and their notes. Extract the notes body placeholders and distinguish narration from titles, footers, and slide numbers. For Keynote and Google Slides, use a native app, authorized connector, or export that preserves slide order and exposes notes. For PDF, map the script in document page order. When an export omits notes, recover them from the original presentation or map a separate script to page numbers.
- Reuse verified slide images when they meet the target. Discover available apps and connectors, or check an installed renderer's version and format support. Export a representative chart or small-text slide first and check fonts, clipping, dimensions, and chart rendering. If the native app is unavailable, verify a compatible export or rasterize a vector PDF directly at the target dimensions. If only low-resolution sources are available, record their dimensions and the resulting clarity limit.
- Choose from the tools available in the current environment. For static slides and narration, look for a tool that can set slide durations, combine images with the final audio track, and export at the target resolution. For staged visuals, use a renderer that supports timed reveals and can export a representative clip. Select editing or asset-processing tools by the operation the project needs. If an optional tool is unavailable, continue with any renderer or editor that can perform the required work.

## Narration, billing, and recovery

- Look for a completed recording, an installed local synthesizer, or an audio service the user has authorized to receive the narration text. Match the user's voice, language, and delivery requirements and verify that the tool can return a usable audio format. Save word timings if available. If remote synthesis is unavailable or unauthorized for this script, use a local option that meets the user's requirements or continue with slides and script and report what is needed. Use a substitute voice when the user allows it.
- Assemble the script in slide order and record each slide's text boundaries. Prefer a full-script recording or synthesis. If a service limit requires multiple requests, split at natural paragraph or chapter boundaries and check voice consistency, loudness, joins, and required service markers before assembling the final single track. Put phonetics and alternate readings for terms and numbers in the synthesis input. Use the approved wording in captions.
- Before a paid submission, record a local request identifier, a digest of the synthesis input, the voice, and the estimated cost in the production directory. Pass the identifier to the service if it supports a client request ID. Count completed, pending, and uncertain charges against the authorized budget. Coordinate concurrent requests against the same ledger and save service receipts with the provider's task ID when available.
- On recovery, query the existing task by its provider ID and download its result when ready. Query again for a fresh URL if the download fails or the link expires. If a submission was interrupted before a receipt arrived, look for the client request in authorized task or billing history where available. Retry only after resolving the earlier request's state and verifying that the retry cannot duplicate it and fits the remaining budget. If charges or acceptance remain uncertain, preserve completed work and continue with stages that incur no new charges.
- Write downloaded audio to a temporary file and check full decoding and duration before marking the result complete. Record request status, billing evidence, audio digest, and timestamps. Record billed charges and estimates separately.

## Timing and pronunciation repair

- Align the script to word timestamps from the final narration. If timings are missing or drift, look for an available local forced aligner or speech recognition tool. A player can supply manual slide and caption timestamps when those tools are unavailable. If actual timings cannot be obtained, retain the assets and identify the sections awaiting alignment. Use recognition output to find a passage and listen to judge pronunciation.
- Place each slide change at the start of its narration and preserve the opening and closing. Maintain one timeline with slide ranges and caption ranges linked to slide numbers. Verify slide order and ensure caption timings increase without overlaps or overruns. Place captions clear of charts and other important content.
- Record the slide, playback time, observed pronunciation, and intended pronunciation. Check product materials, a reliable dictionary, or a vendor example. State the basis for an inferred reading. Capitalized acronyms can trigger letter-by-letter pronunciation, and recognition may produce homophones. Test phonetic markup or lowercased input in a short sample where it helps.
- Re-record a complete passage and splice it into quiet speech gaps with short fades and matched loudness. Listen to adjacent sentences and check for repeated cues and any required closing marker. Update affected slide and caption timings, including downstream cues shifted by a duration change. Compare decoded content outside the edit when practical.

## Export, verification, and archive

- Set the export endpoint from the final narration duration. H.264 with `yuv420p` and AAC is a common MP4 choice for player compatibility. Deliver the requested SRT file, subtitle track, or burned-in captions and preserve any required service markers.
- If FFmpeg tools are available, set `movie` to the local export path. Use `ffprobe -v error -show_streams -show_format -of json "$movie"` to inspect streams, dimensions, duration, and the single narration track. Use `ffmpeg -nostdin -v error -xerror -i "$movie" -f null -` to check full decoding and `blackdetect` to investigate unexpected black frames. If those commands are unavailable, use equivalent media properties and decode checks in an available tool and report any gaps.
- Compare a frame from each slide interval with its source image. Check the first and last scenes, chapter transitions, and caption readability. Play and listen to samples from the beginning, middle, end, and repaired passages. If listening is unavailable, record the outstanding timestamps and provide a playable local file.
- Before uploading or writing to an automatically synced folder, check that the user has authorized sending the movie to that destination. If the target name already exists, compare the bytes and preserve a recoverable version before replacing anything. Copy to the requested local archive or sync folder and compare SHA-256 digests. For cloud delivery, verify the server-side file or download. Record the local copy and cloud verification independently. Keep the verified local movie and report the specific blocker if remote verification is unavailable.
