- `rules/roadmap-quality.md` (v1.0.0): new rule — 路线图制品的 5 维评审清单。`rules/` 下原有 requirement / functional-design / technical-design / task / test-case / test-coverage 六份判据 rule，roadmap 是治理链上唯一缺判据的一层。本文件是路线图判据的**唯一权威源**：`define-roadmap`（生产侧）、`plan-next`（诊断侧）、`review-roadmap`（评审侧）三方引用同一份表述，避免重蹈 `rules/requirement-quality.md` 与 `review-requirements` 各维护一套判据的覆辙。反模式清单由本 rule 自身的五维结构推出，每条对应一维判据的失效形态；涉及的产品管理通用概念在「判据依据」节回溯至公开出版物（《Product Roadmaps Relaunched》、Intercom RICE、《Lean UX》、《Escaping the Build Trap》等）。**制定过程中调研过三个开源 PM 技能仓库，初版曾把其中之一列为判据出处，随后发现该仓库为 CC BY-NC-SA 4.0——其非商业与相同方式共享条款与本仓库 MIT 不兼容，衍生声明会造成许可证冲突。已重写反模式使其从本 rule 的判据结构自洽推出，并将概念出处回溯到一手公开著作，不再声明衍生自任何外部仓库。**另两个调研对象（Apache-2.0 与 MIT）虽许可证兼容，本 rule 亦未复制其表达，故同样不作衍生登记——按 `specs/skill-source-modeling.md`，`SOURCES.yaml` 只登记 vendored 的 Skill 本地副本，行业通用概念与文档链接不登记。
- `skills/map-item-dependencies/SKILL.md` (v1.0.0): new skill — 识别 backlog 与 roadmap 条目间的五类依赖（技术 / 团队 / 外部 / 知识 / 顺序），写入条目 `depends_on`，产出依赖图、需解决时点与削减建议。此前本仓库对条目间依赖完全空白：`promote-roadmap-items` 只按 priority 与容量排序，一个「P0 但被仍在 backlog 的条目阻塞」的项会被正常拉进 Now 占着容量不产出。发现依赖环时 halt 并输出环路径，不自行选边打破——拆哪条边是范围决策，超出依赖登记的职责。`depends_on` 字段语义借用 `rules/task-quality.md` 的既有约定；已知债务：backlog-item 目前无 spec，结构只由 `capture-work-items` 的输出模板隐式定义，若该制品字段继续增长应补 `specs/backlog-item-modeling.md`，此处仅记账不代表已解决。
- `skills/update-roadmap/SKILL.md` (v1.0.0): new skill — 路线图日常运维入口：改状态、挪期并计算下游影响、产出「本次变更了什么」摘要。此前 `define-roadmap` 管从零建、`promote-roadmap-items` 管跨层晋升降级，两者之间的日常动作无处安放。与 promote 的分界写死为「改变层级的归 promote，不改变层级的归本技能」——把 Now 项推迟两周是本技能，把它挪到 Next 是 promote。改为 `at risk` / `blocked` 时阻塞原因与缓解方案缺一不写入；依赖数据缺失时明确声明「下游影响未计算」而非假装已分析。
- `skills/review-roadmap/SKILL.md` (v1.0.0): new skill — 按 `rules/roadmap-quality.md` 评估既有路线图，输出 findings-list。IO 契约对齐既有的 `review-requirements`（`document-artifact` 进、`findings-list` 出）。输入除 roadmap.md 外还包含佐证源——`strategic-goals.md` 与 Now 层引用的 backlog 条目：判据中有三条的数据在条目 frontmatter 里（`strategic_goal_id` / `depends_on` / `priority_decision`），只读 roadmap.md 的话这些维度结构上就无从求值，负责检查的技能读不到要检查的东西。读不到佐证源时标「无法评估」，不得记为通过。**判据不内嵌**，全部引自 rule，这是与 `review-requirements` 现状的刻意差异。变更频率维度依赖 git log，写明了「发现 → 执行 → 缺失处理」路径：非 git 仓库、浅克隆或无提交历史时标注为「无法评估」并说明原因，不得静默跳过或据此推断通过。判据文件缺失时 halt——没有基准就评估，产出的会是一份看似权威实则无依据的清单。**不输出 mode**：编排层的上下文检测由编排层自己做。
- `skills/orchestrate-roadmap-planning/SKILL.md` (v1.0.0): new skill — 编排技能，按固定 9 步串联从战略目标到晋升的原子技能。存在价值是**提前满足下游 halt 条件**：手工调用最常见的浪费是做到 `promote-roadmap-items` 才发现缺容量分配、halt、回头跑 `define-roadmap` 再重来（该回退在 promote 的示例 2 里被当成正常流程写着）。每步标注必选 / 默认 / 推荐三档，档位是各原子技能既有约束的机械映射而非本层判断——步骤 1、2 必选因为对应 promote 明写的 halt 条件；步骤 4 双档位对应 promote 对「全部 unset」halt、对「部分 unset」仅跳过的两种行为；步骤 8 推荐因为 `archive-milestone` 自身 `apply` 默认即为 dry-run。档位同时决定失败语义，这是相对 `orchestrate-code-review` 单一 halt 规则的有意偏离（那里各原子技能彼此独立，这里步骤间有数据依赖）。含与 `plan-next` / `orchestrate-governance-step` 的正交边界表，禁止反向调用以避免调用环。
- Engineering review criteria move out of the Skills that executed them and into versioned Rule sets. They had lived inside the cognitive review Skills, so they could not be applied before coding, configured per project, or cited afterwards. `specs/rule-modeling.md` defines `RULE_MODEL_V1` — stable item identifiers that are never reused, three applicability levels, parameter provenance and the waiver object — and nine Rule sets now carry 102 items across architecture, security, reliability, performance, observability, testing, implementation alignment, task quality and technical design quality. Of those, 53 are baseline and apply wherever the set's scope is present, 42 are gated on a profile and 7 on a declared project parameter. Severity is graded by what happens if a finding is left unfixed, so 63 block the gate rather than all 102: absent evidence such as a missing test or measurement raises future risk rather than causing a present failure, and is minor. `rules/workflow-rule-governance.md` constrains identifier stability, compatibility and the activation evidence each enforcement strength owes — and says when a set should adopt the model at all, which is only when its items must be waived, counted in coverage or cited by another artifact, so requirement and functional design quality deliberately stay checklists. Six review Skills are new (functional design, technical design, tasks, implementation alignment, observability, reliability) and four cognitive reviewers now execute the canonical Rules instead of their own embedded lists. `scripts/validate-rules.py` validates every modeled document and item, and `scripts/test-rule-scenarios.py` decides the 15 items that are both automated and blocking over nine representative shapes drawn from three populations — a library, a layered application and a distributed service. Both run in CI. The four rewritten reviewers went to a major version — `review-architecture`, `review-performance`, `review-security` and `review-testing`, with `review-requirements` alongside them — although their `code-scope → findings-list` contract did not change: what changed was the authority their criteria come from and what completeness now means, which is breaking for a caller relying on the old embedded checklists even though the artifact types still match. Recorded in `docs/adr/0012-adopt-profiled-engineering-rules.md`.
- Five research entries, an internal assessment, and the two contracts they pass between them. `deep-research`, `policy-research`, `market-research`, `competitive-research` and `product-opportunity-analysis` are user-invocable; `assess-product-opportunity` carries the recommendation logic and is internal by repository metadata, while the package entry selects the relevant lanes and aggregates their output. `specs/research-evidence.md` defines a portable Research Report whose decision-relevant statements trace to a source or to an explicit gap, and `specs/opportunity-package.md` the decision layer built on it. `docs/adr/0013-research-skill-entry-names.md` records the narrow naming exception: four of the five names are noun-led and the package entry lacks the usual `orchestrate-` prefix, which is kept because renaming would break commands already promised to users, and it does not loosen the verb-noun rule for anything else. `scripts/test-research-artifacts.py` validates 10 positive fixtures and 26 negative cases in CI, including a conflicting report, a stale source and an inaccessible one. Live routing through an authenticated host is not yet verified; `docs/references/research-skills-smoke-test.md` separates what was checked locally from what still waits.
- Two criteria for code that has outlived its use, which the Rule sets had no item for. `architecture-quality` 1.0.1 → 1.1.0 adds ARC-010 and ARC-011, bringing the nine sets to 104 items. ARC-010 requires code no consumer reaches to be removed rather than commented out, disabled behind a permanent flag or kept in case it is wanted again, and fixes what counts as knowing it is unreached: unused-symbol analysis over the built artifact, plus a runtime signal over one full business cycle for anything the analyzer cannot resolve — reflection, a class named in configuration, dynamic dispatch, a consumer in another repository. Its pass condition says outright that a clean analyzer run is not evidence about a symbol the analyzer cannot see, which is the failure that deletes something month-end still calls. ARC-011 requires a deprecation marker to record who removes it, by which release or date, and what a caller migrates to; a marker carrying none of the three is a second implementation kept indefinitely rather than a migration in progress. Both are `minor` and `tool-assisted`, graded by the set's own rule that debt raising future cost does not block a gate the way a present failure does. `review-architecture` picks them up with no change to its execution, since it runs whichever items the active Rule version carries; 2.0.1 → 2.1.0 adds a worked example for each, because both turn on a distinction a reviewer gets wrong by default — an analyzer reporting nothing is not a pass for what it cannot resolve. Neither owes a fixture test — constraint 8 of `rules/workflow-rule-governance.md` asks that of automated blocking items — but the half of each that is mechanical, deciding the obligation once the evidence is in hand, is pinned in `scripts/test-rule-scenarios.py` regardless, over a fourth shape that brings it to 10: a plugin host that loads handlers by name from configuration, where static analysis is weakest. Writing those cases found a hole in ARC-010 as first published: its pass condition let any removal through, so deleting a reflection-reached symbol on the analyzer's word alone would have passed — the exact failure the item was written to prevent. The condition now requires a runtime signal in that direction too. Seven mutations of the decision were seeded and all seven were caught. `review-implementation-alignment` 1.0.0 → 1.1.0 states the boundary rather than taking the items on: delivered code nothing reaches is its own, under ALN-003, but the implementation a change replaced and left behind is ARC-010's, decided by the sibling engineering gate over the same scope. The two read alike and would otherwise be reported twice or by neither. `review-codebase` 1.0.1 → 1.1.0 names both in its tech-debt dimension, which is where a reader first meets them, and routes the decision rather than taking it: neither is settled by reading the code, since one needs a runtime signal and the other needs the fields recorded beside the marker.
- The link checker's fixtures grow from two seeded defects to seven mutations, matching the other three checks. The tree gains an anchor that must still resolve, an absolute URL and a mail address that are not repository paths, and a guide outside `rules/`, `specs/` and `protocols/` linking a Skill directly — the reference-direction rule binds governance assets, not prose, and nothing had been asserting that. All seven are caught: the code-span strip, the fence matched at any indent, the fence closed on its own marker length so a longer one can hold a shorter, the fence skip itself, the absolute-link exclusion, the anchor strip, and the governance gate.
- The reachability and filename checks get the fixture tree they had been running without. `tests/fixtures/doc-graph` carries an orphan, a tombstone unlinked on purpose, a directory README that is an entry point rather than an orphan, a backup beside the file it copies, a link shown inside a fence that must not make its target reachable, and two lowercase names — `review-security.md` and `release-notes.md` — that the uppercase process-record words must not fire on. Seven mutations were seeded and all seven caught, but three only after the shapes were extended: nothing had distinguished a legitimate lowercase name whose token is on the list, and nothing had exercised the fence skip. A fourth mutation survived because the code it targeted reached nothing — resolving a link to a directory into that directory's index, which changes no reachability when every index and README is already an entry point. It is deleted rather than given a fixture, on the same reasoning ARC-010 states.
- The temporary-document patterns are enforced, not just written down. `scripts/check-doc-hygiene.py` gains a third check and the CI step covers it, decided the way the rule reads: a body pattern identifies a document as temporary, and constraint 4 then requires such a document to carry a dated or `.draft` name inside a dedicated directory. The finding is therefore an unlabelled one — the same sentence is compliant in `docs/designs/2026-09-17-…` and a defect in a Spec. An ADR is exempt because narration is its genre, the changelog because it is narration throughout, and a pattern is exempt where it is shown rather than used: under an anti-pattern heading, marked with a cross, inside a fence, or inside quotation marks. That last one carries most of the weight, since `write a rule, not "we decided to follow the convention"` quotes what it forbids. `scripts/test-doc-hygiene.py` pins it over ten shapes, and seven mutations of the decision were seeded and all seven caught — two of them only after the shapes were extended, because a dated name outside a dedicated directory had no fixture and one mutation had been silently rewriting the wrong function.
- Eleven review Skills drop their `## Change record` section, each taking a patch bump. `rules/workflow-documentation.md` treats version narration in a body as a temporary-document marker and sends it to the changelog, and the sections had drifted into exactly that — "Version 2.0.1 removes a stale example pin" and the like. The descriptive bullets beside them restated what the frontmatter and the body already say. One thing they held was recorded nowhere else and is preserved above: why four reviewers took a major version although their artifact types stayed compatible. The rule's own grep list was Chinese-only and caught none of them.
- `workflow-documentation` 1.0.0 → 1.1.0 enumerates the English grep set the rule had been promising, for both body patterns and conversational residue. Every candidate was measured against the repository before it went in, and two were dropped on the numbers: `\bTBD\b` fired 19 times, nearly all of them Skills telling an agent to write `TBD` where a value cannot be inferred, and `\bto be built\b` fired on a metric whose data source is genuinely pending — a pattern whose hits are mostly legitimate only teaches a reader to skim past the report. The finished set matches two documents across 244. Neither is a violation: the rule's constraint 4 says a body pattern identifies a document as temporary and such a document must then be labelled, so a dated design snapshot citing "the earlier discussion" is compliant, and the other hit quotes the form inside quotation marks. The exception for a pattern shown as a counter-example widens from this rule alone to any Rule or Spec quoting one in a labelled anti-pattern list, which is what four of the six raw hits were.

Eight real orphans were found and cleared; four design snapshots and a smoke record now hang off a new `docs/designs/README.md`. ### Fixed

- Eight dead links under `docs/adr/`, and the CI allowlist that excused them. The link job skipped every broken link in that directory, on the stated grounds that older records deliberately reference assets since deleted. Six of the eight were not that: written as `../../../specs/skill.md` from `docs/adr/`, they climb past the repository root and never resolved, one of them beside a correctly written link in the same table. Each is downgraded to its label text under the maintenance `rules/adr-management.md` §4 now permits — no word of any record changed, and no link repointed at a renamed successor. The allowlist is gone, so a broken link anywhere fails the build.
- The numbered procedures in `docs/guides/protocols-usage.md`, whose rendered numbering did not survive. Each step's code block sat at column zero, and a fence at column zero ends the list, so every following step began a fresh list that restarted at one. Eleven blocks are indented into the item they belong to. markdownlint's own autofix would instead have renumbered the steps to 1./1./1., preserving the broken structure. A table row in `docs/guides/research-skills-usage.md` was also missing its leading pipe.
- Two CI guards that could not tell a link from a document showing what a link looks like. `rules/workflow-documentation.md` grants itself that exception in prose — a rule defining a no-go zone has to display the forms it forbids — but the greps enforcing reference direction and relative links did not honour it, so `rules/adr-management.md` had to carry a fabricated path in its counter-example. Both now share one extractor in `scripts/check-markdown-links.py`, which skips code spans and fences, matches a fence at any indent (the previous one required column zero, and blocks nested in list items are indented) and closes a fence on its own marker. `scripts/test-markdown-links.py` asserts it against a fixture tree; two seeded defects confirmed the test can fail.
